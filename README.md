# КП · Bitrix24 — локальный генератор коммерческих предложений

**КП · Bitrix24** — локальное приложение для Windows, macOS или Linux, которое берёт данные CRM-сделки Bitrix24, подставляет их в ваш фирменный Word- или PowerPoint-шаблон и выдаёт готовое коммерческое предложение в нативном `.docx`, `.pptx` или PDF. Шаблоны, сгенерированные документы и доступ к Bitrix24 сохраняются **только на вашем компьютере**.

## Два способа подключения уже предусмотрены

| Подход | Особенности | Стоимость | Сложность запуска |
|---|---|---|---|
| **Входящий вебхук** | Открываете конструктор по `127.0.0.1`, вводите ID сделки и формируете КП. Подходит для одного портала и быстрого начала работы. | Нет отдельной стоимости, кроме требований вашего тарифа Bitrix24 к REST API. | Низкая: создать вебхук и вставить его URL. |
| **Локальное приложение Bitrix24** | Конструктор открывается из интерфейса Bitrix24 и получает авторизацию пользователя. Также требуется для устойчивой автоматизации по исходящим событиям. | Сам сервис локальный; для постоянного доступа нужен ваш публичный HTTPS-адрес или корпоративный сервер. | Средняя: нужен публичный HTTPS-туннель при работе с ноутбука и регистрация приложения в Bitrix24. |

В приложении реализованы **оба варианта**, поэтому начать можно с вебхука, а затем без переустановки перейти к меню Bitrix24 и автоматическим событиям.

## Источник табличной части — файл в комментарии сделки

С учётом вашего процесса приложение не ограничивается товарными строками CRM. В мастере формирования КП есть кнопка **«Найти спецификации в комментариях сделки»**. Она получает список файлов из `crm.timeline.comment.list`, позволяет выбрать нужное вложение и передаёт его через безопасный подписанный URL Bitrix24 на локальный разбор. Поддерживаются таблицы в `.xlsx`, `.xls`, `.xlsm`, `.csv`, `.docx`, `.pptx` и текстовом `.pdf`.

Выбранная спецификация становится источником позиций, количества, единиц измерения, цен, сумм и комментариев. Сделка при этом остаётся источником клиента, контактов, менеджера, названия проекта и общего итога. Перед генерацией приложение показывает строки и предупреждения: если у позиции не найдено количество или цена, это не скрывается и требует проверки. В автоматическом режиме по событию сделки берётся **самая новая подходящая спецификация из комментариев**; если файл не найден или не распознан, КП не создаётся с неверными данными.

Файл спецификации скачивается во временное локальное хранилище только на время разбора и удаляется после обработки. Оригинальное вложение в Bitrix24 не меняется. Если в комментарии несколько файлов, в ручном режиме выбирается конкретный файл, поэтому старую спецификацию нельзя случайно принять за актуальную.

## Что умеет приложение

| Возможность | Как работает |
|---|---|
| Формировать КП из сделки | Получает название, сумму, клиента, контакт, ответственного и позиции сделки через Bitrix24 REST API. |
| Работать с вашими шаблонами | Загружает `.docx` и `.pptx` до 20 МБ и показывает найденные метки. Исходный файл не изменяется. |
| Подставлять реквизиты | Подставляет реквизиты продавца, клиента, менеджера и сделки, а также пользовательские поля сделки. |
| Создавать таблицу товаров | В Word строит таблицу по метке `{{products.table}}`, а в PowerPoint заполняет существующую нативную таблицу товаров. |
| Сохранять редактируемость | PPTX остаётся PowerPoint-презентацией: текстовые блоки и таблицы можно редактировать, а в таблицах можно добавлять и удалять строки и столбцы уже после генерации. |
| Проверять перед созданием | Показывает значения меток до формирования и позволяет разово их исправить, не меняя CRM. |
| Создавать автоматически | При событии добавления или изменения сделки сохраняет КП локально по выбранному шаблону и стадии. |

> **Что приложение намеренно не делает:** оно не изменяет данные сделки и не прикрепляет документы обратно в Bitrix24. Это сохраняет первый запуск безопасным и обратимым. Эти функции можно добавить отдельным этапом после проверки ваших шаблонов и бизнес-процесса.

## Быстрый локальный запуск

### 1. Установите Python

Нужен **Python 3.11 или новее**. При установке в Windows отметьте пункт `Add Python to PATH`.

### 2. Установите зависимости и запустите сервис

Откройте Terminal (macOS/Linux) или PowerShell (Windows) в папке проекта.

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

**Windows PowerShell:**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
py run.py
```

После запуска откройте [http://127.0.0.1:8787](http://127.0.0.1:8787). Адрес доступен только на вашем ноутбуке.

Для выдачи PDF дополнительно установите [LibreOffice](https://www.libreoffice.org/download/download-libreoffice/). Формирование нативных Word- и PowerPoint-файлов работает и без него.

## Подключение к Bitrix24

### Вариант A — входящий вебхук: рекомендован для первого запуска

Это самый простой способ для одного портала и одного ноутбука.

1. В Bitrix24 откройте **Приложения → Ресурсы разработчика → Готовые сценарии → Другое → Входящий вебхук**.
2. Выдайте права **CRM** и **Пользователи**. Вебхук работает в пределах прав сотрудника, который его создаёт.
3. Создайте вебхук и скопируйте его полный адрес. Он выглядит так: `https://ваш-портал.bitrix24.ru/rest/1/секретный_код/`.
4. В приложении откройте **Настройки**, оставьте режим «Входящий вебхук», вставьте URL и сохраните.
5. Нажмите **Проверить доступ**. Пароль-подобный URL не показывается в браузере после сохранения и лежит в локальном файле `data/settings.json`.

Входящий вебхук подходит для локальной интеграции с одним аккаунтом Bitrix24; он вызывает REST-методы от имени его владельца. Официальная справка Bitrix24: [авторизация REST API](https://apidocs.bitrix24.com/settings/how-to-call-rest-api/authorization.html) и [вебхуки](https://apidocs.bitrix24.com/local-integrations/local-webhooks.html).

### Вариант B — локальное приложение внутри интерфейса Bitrix24

Выбирайте этот вариант, если хотите открыть конструктор как пункт меню Bitrix24. Для этого Bitrix24 должен иметь возможность обратиться к ноутбуку по **публичному HTTPS-адресу**; `localhost` для него недоступен.

1. Запустите приложение локально, как описано выше.
2. Поднимите временный HTTPS-туннель, например Cloudflare Quick Tunnel:

   ```bash
   cloudflared tunnel --url http://127.0.0.1:8787
   ```

   Команда выведет адрес наподобие `https://случайное-имя.trycloudflare.com`. Пока нужен доступ из Bitrix24, окно с туннелем и окно с приложением должны оставаться открытыми.
3. В Bitrix24 перейдите в **Приложения → Ресурсы разработчика → Готовые сценарии → Другое → Локальное приложение**.
4. Создайте **серверное локальное приложение с интерфейсом**. В поле **Путь обработчика** укажите `https://случайное-имя.trycloudflare.com/bitrix/app`. Выдайте права **CRM** и **Пользователи**.
5. Откройте созданное приложение из меню Bitrix24. Bitrix24 передаст краткоживущую авторизацию через защищённый запрос, после чего интерфейс откроется во фрейме.

Серверное локальное приложение с интерфейсом использует упрощённый OAuth-сценарий и работает от имени сотрудника, который его открыл. Перед настройкой проверьте, что у портала есть доступ к REST API и у вас есть право создавать приложения. Официальная инструкция: [локальные приложения](https://apidocs.bitrix24.com/local-integrations/local-apps.html) и [серверное приложение с интерфейсом](https://apidocs.bitrix24.com/local-integrations/serverside-local-app-with-ui.html).

## Как подготовить Word- или PowerPoint-шаблон

1. Сделайте **копию** фирменного бланка в формате `.docx` или `.pptx`.
2. Для Word вставьте метки в текстовые поля, абзацы, колонтитулы или ячейки таблиц. Для PowerPoint — в текстовые блоки или ячейки нативных таблиц.
3. Каждая метка должна быть набрана одним цельным фрагментом; не применяйте разное начертание к отдельным символам внутри неё.
4. Загрузите файл в раздел «Шаблоны» приложения.

PowerPoint-файл не преобразуется в изображение: приложение редактирует исходный `.pptx` как презентацию. Поэтому после генерации получатель сможет открыть файл в PowerPoint, менять текст, а в нативной таблице добавлять, удалять и редактировать строки и столбцы. При этом исходный шаблон не изменяется.

В папке `examples` лежит готовый [пример Word-шаблона](examples/Шаблон_КП_пример.docx) и копия вашего [PPTX-шаблона «Корпорация Маяк»](examples/Пример_КП_Корпорация_Маяк_исходник.pptx). Последний можно загрузить напрямую: в нём уже распознаны нативные таблицы `hardware-table` и `budget-table`.

| Группа | Метки |
|---|---|
| Номер и дата | `{{document.number}}`, `{{document.date}}` |
| Сделка | `{{deal.id}}`, `{{deal.title}}`, `{{deal.amount}}`, `{{deal.currency}}`, `{{deal.stage}}`, `{{deal.close_date}}`, `{{deal.comments}}` |
| Клиент | `{{client.company}}`, `{{client.contact_name}}`, `{{client.phone}}`, `{{client.email}}`, `{{client.address}}`, `{{client.inn}}` |
| Менеджер | `{{manager.name}}`, `{{manager.phone}}`, `{{manager.email}}` |
| Ваша компания | `{{seller.name}}`, `{{seller.inn}}`, `{{seller.phone}}`, `{{seller.email}}`, `{{seller.address}}` |
| Итог и позиции | `{{products_total}}`, `{{products.table}}` |
| Пользовательское поле сделки | `{{deal.custom.UF_CRM_123456789}}` — замените код на фактический код поля вашего портала. |

Чтобы создать таблицу позиций в Word, поставьте в отдельном абзаце метку `{{products.table}}`. При формировании она заменяется таблицей «№ / Наименование / Кол-во / Ед. / Цена / Сумма». В PowerPoint используйте существующую нативную таблицу: если её имя содержит `hardware-table`, `product` или `комплект`, приложение заполнит её товарными позициями, сохранив таблицу редактируемой. Последнюю строку таблицы использует как итоговую. Таблица с именем `budget-table`, `summary` или содержащая `стоим` получает сумму товаров в первой строке и общую сумму сделки в итоговой строке. После создания число строк и столбцов можно свободно менять в PowerPoint.

Для вашего предоставленного файла автоматически распознаются смысловые имена объектов `cover-title`, `cover-customer`, `total-number`, `contact-name`, `contact-company` и `contact-details`. Они получают данные сделки, клиента и менеджера даже без ручной расстановки меток. Для остальных текстовых блоков можно добавить стандартные метки из справочника.

## Автоматическое формирование по событию сделки

Автоматика нужна, если КП должно появляться после смены стадии, создания или изменения сделки без открытия локального интерфейса.

1. Убедитесь, что приложение запущено, и у него есть публичный HTTPS-адрес. Для теста подойдёт туннель из варианта B выше.
2. В Bitrix24 создайте **Исходящий вебхук**: **Приложения → Ресурсы разработчика → Готовые сценарии → Другое → Исходящий вебхук**.
3. Введите обработчик: `https://ваш-публичный-адрес/bitrix/events/deal`.
4. Выберите события добавления и/или изменения сделки (`ONCRMDEALADD`, `ONCRMDEALUPDATE`), создайте вебхук и скопируйте его **токен приложения**.
5. В разделе «Настройки» включите автоматизацию, выберите шаблон, при необходимости укажите системный код стадии (например, `PREPARATION`) и вставьте защитный токен. Сохраните.
6. Измените тестовую сделку. При подходящем событии нативный файл выбранного шаблона (`.pptx` или `.docx`) появится в «Последних документах» и в `data/documents`.

Приложение проверяет `auth[application_token]`, который Bitrix24 отправляет с событием. Если токены не совпадают, документ не создаётся. Bitrix24 требует, чтобы обработчик исходящего вебхука был доступен извне по HTTPS; `localhost`, адрес локальной сети и самоподписанный сертификат не подходят. Подробности: [исходящие вебхуки Bitrix24](https://apidocs.bitrix24.com/local-integrations/local-webhooks.html).

> Если ноутбук, приложение или туннель выключены, Bitrix24 не сможет передать событие, и КП не будет сформировано. Для постоянной автоматизации лучше развернуть тот же сервис на вашем корпоративном сервере с HTTPS, а не держать личный ноутбук включённым.

## Данные и безопасность

| Где хранится | Содержимое |
|---|---|
| `data/settings.json` | Настройки, URL входящего вебхука, авторизационный токен локального приложения и токен проверки события. Файл создаётся с ограниченными правами на macOS/Linux. |
| `data/templates/` | Загруженные Word- и PowerPoint-шаблоны. |
| `data/documents/` | Сформированные Word, PowerPoint и PDF-файлы. |
| `data/document_history.json` | Локальный журнал последних 200 сформированных файлов. |

Не добавляйте папку `data/` в Git или в публичные облачные папки. Чтобы полностью отозвать доступ вебхука, удалите или перевыпустите его в Bitrix24, а затем удалите `data/settings.json` на ноутбуке.

## Проверка и диагностика

| Симптом | Что проверить |
|---|---|
| «Не удалось связаться с Bitrix24» | Полный URL вебхука, доступ к интернету, срок действия вебхука и доступность REST API на тарифе портала. |
| «Недостаточно прав» | Права вебхука **CRM** и **Пользователи**, а также права его владельца на конкретную сделку. |
| Клиент или товары пусты | У сделки должны быть привязаны компания/контакт и товарные позиции. Проверьте данные в карточке CRM. |
| Часть меток не заменилась | Убедитесь, что имя метки верное и метка не разделена форматированием. Посмотрите найденные метки после загрузки шаблона. |
| Не создаётся PDF | Установите LibreOffice и перезапустите приложение. |
| Автоматизация не срабатывает | Проверьте, что ноутбук и HTTPS-туннель включены, URL обработчика точно оканчивается на `/bitrix/events/deal`, включена нужная автоматизация и совпадает токен исходящего вебхука. |

## Запуск в защищённой локальной сети

По умолчанию приложение слушает только `127.0.0.1`, поэтому не доступно другим устройствам. Если вы осознанно запускаете его на корпоративном сервере, поставьте перед ним HTTPS reverse proxy, ограничьте сетевой доступ и задайте стабильный `CP_SECRET_KEY` через переменную окружения. Не открывайте URL входящего вебхука и файл `data/settings.json` пользователям браузера.

## Лицензия и дальнейшее развитие

Проект подготовлен как стартовый локальный сервис. Перед использованием в рабочем процессе рекомендуется протестировать его на копии шаблона и тестовой сделке. Возможные безопасные расширения: прикрепление готового файла в таймлайн сделки, несколько маршрутов шаблонов по воронке/стадии и журнал аудита с пользователем, который сформировал документ.
